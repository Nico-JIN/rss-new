# RSS News 热点检测系统技术文档 (v2)

本系统采用“自下而上”的**叙事涌现模型**，通过本地高效聚类与大语言模型（LLM）语义分析相结合，实现从海量杂乱新闻中自动提取真实世界正在发生的重大叙事。

---

## 核心流程全解析

系统的整个检测周期分为以下四个核心阶段：

### 1. 数据打捞与初步清洗 (Retrieval & Filter)
*   **目标**：打破关键词搜索的局限，构建全量分析池。
*   **逻辑**：
    *   根据配置的时间窗口（如最近 24 小时）从 `news.db` 中提取所有符合条件的文章。
    *   **中国媒体过滤**：根据 `exclude_china_media` 参数，实时剔除大陆官方媒体（新华社、环球等），确保情报池的纯净度和独立视角。
    *   **预处理**：对标题进行标准化，提取分词和命名实体。

### 2. 本地快速聚类 (Local Clustering)
*   **目标**：利用本地算力，将千级规模的文章快速缩减为十位级的“候选事件簇”。
*   **逻辑**：
    *   使用一种改进的增量聚类算法。
    *   **相似度计算 (`_calc_similarity`)**：
        *   **实体重合度 (50%)**：对比人名、地名、机构名。包含“巴格达”、“Nvidia”等特异性实体会极大提升相似度。
        *   **词汇交集 (30%)**：计算去停用词后的 Jaccard 相似度。
        *   **滑动窗口比对 (20%)**：针对标题微调进行字符匹配。
    *   **降噪控制**：**惩罚通用词**。如果重叠词仅包含“美国”、“总统”、“政府”等泛化词，则分数直接衰减，防止无关新闻因“共词”被错误缝合。

### 3. LLM 叙事提炼 (LLM Narrative Extraction)
*   **目标**：引入“编辑思维”，解决机器聚类无法理解逻辑细节的问题。
*   **逻辑**：
    *   将聚类后文章数最多的 Top 12 个簇送入 LLM。
    *   **压缩 Prompt**：每个簇只选取前 3 条最具代表性的标题（且截断到 60 字），极大节省 Token 并缩短响应时间。
    *   **LLM 职责**：
        *   **逻辑验证**：判断该簇内的文章是否真的属于同一叙事，剔除无关噪音。
        *   **二次命名**：不再使用原标题，而是由 LLM 书写一个能够概括多方报道核心的“专业新闻综述标题”。
        *   **自动标签**：由 LLM 重新定义该事件最准确的实体标签。

### 4. 热度评分与分类 (Scoring & Delivery)
*   **目标**：量化事件影响力，并将其精准投放到前端面板。
*   **评分公式**：
    *   `Score = (跨媒体数 * 8) + (文章总数 * 2) + 媒体权重 + 时效性得分 + 持续报道加成 + 中国相关加成`
    *   **媒体权重**：Reuters (路透社)、AP (美联社) 等 Tier 1 媒体会带来显著的分数加成。
*   **分类路由**：
    *   系统会扫描事件标题和标签。
    *   若命中“白宫、五角大楼”则送入【美国新闻】；若命中“日本、冲绳”则送入【日本新闻】。

## 策略调整与优化

你可以通过修改 `config/hotspot_schedule.yaml` 来灵活调整系统行为：

| 参数 | 说明 | 优化建议 |
| :--- | :--- | :--- |
| `hours` | 检测时间跨度 | 突发期间建议设为 3-6，回顾建议设为 24-48 |
| `exclude_china_media` | 是否排除中媒 | 全球情报分析建议设为 `true` |
| `similarity_threshold` | 聚类阈值 | 若发现热点分得太散，建议调低（如 0.25）；若太乱，调高（如 0.45） |

> [!TIP]
> **熔断保护机制**: 如果大模型接口（如 Gemini 或 DeepSeek）因为网络波动无法响应，系统会立即自动切换到“本地降级模式”，虽然标题没有大模型写得好，但能保证前端 100% 不开天窗。
