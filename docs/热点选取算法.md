# 热点事件检测算法

## 概述

本模块实现了轻量级本地热点检测算法，无需依赖 LLM，毫秒级响应，支持任意时间窗口（3h/6h/12h/24h等）。

## 设计原则

1. **纯本地算法**：不依赖 LLM，避免 Token 消耗和超时问题
2. **动态时间窗口**：支持 3h、6h、12h、24h、48h 等任意时段
3. **多维度评分**：跨媒体、连续报道、媒体权威度、时效性、中国相关
4. **独立模块**：不影响现有功能，可单独调用

---

## 算法流程

```
全部文章 (500篇)
    ↓ [第一级] 跨媒体聚类 (本地，毫秒级)
事件簇 (80个)
    ↓ [第二级] 热度评分筛选 (本地，毫秒级)
候选热点 (25个)
    ↓ [第三级] 排序取 Top N
最终热点 (15个)
```

---

## 核心算法

### 1. 文章聚类算法

**目标**：将报道同一事件的文章归为一簇

**相似度计算公式**：

```
相似度 = 词汇Jaccard × 0.4 + 实体重合度 × 0.4 + 字符相似度 × 0.2
```

**词汇Jaccard**：
```python
words1 = tokenize(title1)  # 分词
words2 = tokenize(title2)
jaccard = |words1 ∩ words2| / |words1 ∪ words2|
```

**实体重合度**：
- 提取命名实体（人名、地名、机构名）
- 实体完全匹配时得分 0.8
- 部分匹配按比例得分

**聚类策略**：
- 增量聚类，避免 O(n²) 两两比较
- 相似度阈值 0.35（可调）

### 2. 热度评分模型

**总分公式**：

```
总分 = 跨媒体分 + 文章数分 + 权威度分 + 时效性分 + 连续报道分 + 中国相关分
```

#### 各维度评分细则

| 维度 | 计算方式 | 分值范围 | 说明 |
|------|----------|----------|------|
| 跨媒体分 | 媒体数 × 8 | 16-∞ | **核心指标**，至少2家媒体才计入 |
| 文章数分 | min(文章数 × 2, 20) | 0-20 | 上限20分 |
| 权威度分 | (平均媒体权重 - 1) × 10 | 0-5 | 核心媒体加成 |
| 时效性分 | 根据最新报道时间 | 0-10 | 3h内10分，6h内7分，12h内4分，24h内2分 |
| 连续报道分 | 时间覆盖度 × 15 | 0-15 | 跨多个时段报道加成 |
| 中国相关分 | 标题含中国关键词 | 0-12 | 与中国相关加12分 |

### 3. 连续报道加成

**计算方法**：
1. 将时间窗口划分为 N 个时段（每2小时一个桶，最多12个）
2. 统计每个时段是否有报道
3. 覆盖时段越多，加成越高

**示例**：
- 事件A：6小时内3个时段都有报道 → 加成 15 × (3/3) = 15分
- 事件B：24小时内仅在1个时段报道 → 加成 0分

### 4. 媒体权威度权重

| 等级 | 媒体示例 | 权重 |
|------|----------|------|
| Tier 1 | 路透社、美联社、纽约时报、BBC、华尔街日报 | 1.5 |
| Tier 2 | 半岛电视台、NHK、联合早报、南华早报 | 1.3 |
| Tier 3 | 新华社、人民日报、澎湃、财新 | 1.2 |
| 其他 | 一般媒体 | 1.0 |

## API 接口

### 快速热点检测

```bash
# 获取最近 6 小时热点
GET /api/intelligence/hot/fast?hours=6&max=15

# 获取最近 24 小时热点
GET /api/intelligence/hot/fast?hours=24&max=20
```

**参数**：
- `hours`: 时间窗口（小时）
- `max`: 最大返回数量

**响应示例**：
```json
{
  "events": [
    {
      "title": "美国宣布对华新制裁措施",
      "score": 58.5,
      "media_count": 8,
      "article_count": 12,
      "platforms": ["路透社", "纽约时报", "华尔街日报", ...],
      "tags": ["美国", "中国", "制裁", "贸易"],
      "is_china_related": true,
      "article_ids": [101, 102, 103, ...]
    }
  ],
  "hours": 24
}
```

### 原有接口（支持快速模式）

```bash
# 使用快速本地算法（默认）
GET /api/intelligence/hot?period=day&fast=true

# 使用 LLM 聚类（慢，不推荐）
GET /api/intelligence/hot?period=day&fast=false&provider=deepseek
```

## 配置调优

### 调整聚类阈值

```python
# 默认阈值 0.35，可根据实际情况调整
clusters = _cluster_articles(articles, threshold=0.35)

# 阈值越高，聚类越严格（同一事件的文章可能被拆分）
# 阈值越低，聚类越宽松（不同事件可能被合并）
```

### 调整评分权重

在 `_calc_cluster_score` 函数中修改各维度权重：

```python
cross_media_score = media_count * 8    # 跨媒体权重
article_score = min(article_count * 2, 20)  # 文章数权重
freshness_score = ...                   # 时效性权重
continuous_score = ...                  # 连续报道权重
china_score = 12                        # 中国相关固定加分
```

### 添加新的核心媒体

在文件顶部的 `TIER1_MEDIA`、`TIER2_MEDIA`、`TIER3_MEDIA` 集合中添加。

---

## 与 LLM 方案对比

| 维度 | 本地算法 | LLM 聚类 |
|------|----------|----------|
| 响应速度 | < 1秒 | 30-60秒 |
| Token 消耗 | 0 | 高 |
| 成本 | 免费 | 付费 |
| 准确度 | 可控、可调优 | 不稳定 |
| 可扩展性 | 优秀 | 受限于 Token |
| 适用场景 | 实时查询、高频调用 | 低频深度分析 |

**推荐策略**：
- 日常使用：本地算法（快速、免费）
- 深度分析：选择热点后，使用 LLM 撰写报告
