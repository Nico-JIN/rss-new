核心概览

流水线由 run_pipeline 驱动，串联文章筛选、LLM 批量抽取、event_key 归一、规则聚合、六大分类打标以及重点回填，最终把结果写入 scheduled_hotspots 并对外提供 get_category_hotspots / run_all_categories API。配置来自 config/hotspot_schedule.yaml、category_rules.yaml 和 feeds.yaml，保证评分、S级媒体及关键字可调。

阶段拆解

1. 配置初始化

  • 读取 LLM、调度、评分与 S 级媒体配置，构建运行上下文。
  • CLI 参数（hours/min_hotspots/provider/dry-run）决定窗口与行为。
  • 数据库连接通过 get_conn / init_db 准备。

2. 待分析文章 & LLM 抽取

  • get_unanalyzed_articles 在时间窗口内抓取最多 2000 篇原始稿件。
  • 批量送入 extract_all_sync，必要时退回规则引擎。
  • 保存结构化事件（event_key、entities、countries 等）供后续使用。

3. 规则聚合 & 评分

  • normalize_event_keys 基于相似度 + pinning keywords 归并事件。
  • run_aggregation（含 aggregate_hotspots）融合多家媒体。
  • 评分 = S 级权重 + 普通媒体 + 来源覆盖，不足阈值直接过滤。

4. 分类打标

  • classify_all_hotspots 依据 primary/related country 规则映射六大类。
  • foreign_china 排除纯国内媒体，包含“缇庡獟/鏃ュ獟”等关键词可强制匹配 US/JP。
  • 同一热点可属于多个分类，内部按 score 降序。

5. 重点回填

  • 对 foreign_china / us_news / japan_news 等重点类执行 backfill_categories。
  • 若数量不足 min_hotspots，从历史已分析文章补齐，优先含 pinning keywords。
  • 自动赋分并补齐 S 级媒体标签，保障每类 ≥5 条稳定输出。

6. 落库 & API

  • 非 dry-run 情况，将各分类 JSON 写入 scheduled_hotspots。
  • stats 记录窗口、来源数与耗时，便于观测。
  • get_category_hotspots / run_all_categories 直接复用入库快照。

数据流 & 关键输入输出

阶段 输入 主要函数 输出
文章准备 窗口内原始稿件 + feed 配置 get_unanalyzed_articles, load_llm_config 未结构化文本批次
LLM 抽取 批量文本、规则黑/白名单 extract_all_sync, save_extraction_results 包含 event_key / entities 的结构化事件
聚合 & 评分 结构化事件 + S 级媒体列表 normalize_event_keys, run_aggregation, load_scoring_config HotspotEvent（score、articles、sources）
分类 & 回填 HotspotEvent + 历史文章 classify_all_hotspots, backfill_categories 每类热点列表（满足最小数量）
持久化 & API 分类结果 + 运行统计 save_hotspots_to_db, get_category_hotspots scheduled_hotspots 表 + JSON stats

检查要点

  • category_rules.yaml.scoring 决定 S 级媒体权重与最低得分，调高可强化噪声过滤。
  • 回填依赖 get_analyzed_articles，若想覆盖更多重点国家，需保证抽取阶段留存原始文章。
  • dry-run 仅跳过 save_hotspots_to_db，但会返回完整 stats 与分类结果，便于调试。
  • API 层仅读取入库快照；如需实时最新结果，请先运行 CLI / 调度再刷新前端。
